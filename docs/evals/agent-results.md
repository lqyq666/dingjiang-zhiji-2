## 后端拒绝与复现

错号通过实际 MCP 进程和正式 Integration API 拒绝。跨项目事项通过 Integration HTTP 直连验证，调用凭证同时具备两个项目的权限。旧版本和正确版本搭配过期状态指纹均通过正式写入路径触发 `STALE_VERSION`。回放只在真实提交后丢弃响应，原命令重放返回已存回执。 [真实进程用例](../../apps/api/src/integration/real-e2e.integration.test.ts) · [跨项目用例](../../apps/api/src/integration-http.integration.test.ts)

### 业务试用仍缺少的条件

- **一致的业务场景。** 现有定位夹具将首个可写的方案事项改名为「产能负荷核对」，保留了其 BOM 方案处理步骤与产出要求。该场景能证明自然语言定位和原文持久化，不能据此宣称产能业务已经完成。下一轮材料闭环应使用名称、输入、处理步骤与验收标准一致的新场景版本，原定位任务及历史评分保留。 [合成夹具](../../scripts/demo/mcp-agent.mjs) · [原事项模板](../../apps/api/src/projects/task-templates.ts)

- **持续使用与真人反馈。** 当前入口结束时会清理临时库。持久试用环境、企业资料和真实非开发者反馈未执行；真人试用仍为 `NOT_RUN`。
