# VS01 Acceptance

> 历史切片说明：本文件保留 VS01 原始验收范围。当前交互口径由 VS13 覆盖：日常责任动作在原位置展示内容与影响后一次提交；误操作通过带原因的补偿恢复，不再增加纯预览确认层。

## Clean Start

- [ ] 从 contract-freeze commit 的干净 checkout 安装依赖。
- [ ] 只启动本地 PostgreSQL、API 与 Web；不连接远端 Supabase。
- [ ] 运行版本化 migration 和固定 fixture seed。

## Browser Journey

- [ ] `/boss` 显示 OTD 71%、目标 85%、延期订单和待处理动作。
- [ ] `/employee` 显示订单 `SO-202608128` 和待确认候选判断。
- [ ] 任务页显示延期 5 天、BOM 晚 4 天、采购启动晚 3 天。
- [ ] 证据抽屉显示文件、sheet、行号和原始字段。
- [ ] 证据抽屉以中文业务名称为主，底层来源对象、版本编号和真实文件名可按需展开。
- [ ] 六个经营改善流程节点均可点击；已完成节点可回看，审批节点能进入老板驾驶舱，未实现节点明确展示边界。
- [ ] BOM、采购和产能情况分别显示所需材料与解决方法，PMC 能登记材料引用并刷新完成状态。
- [ ] AI 辅助窗口只输出 `DEMO_RULES / PROPOSAL` 建议，可填入判断草稿但不能自动保存决策。
- [ ] PMC 能选择确认、修改或信息不足；刷新后 Decision 仍存在。
- [ ] 保存人工判断的原表单展示选择、备注、状态影响和撤销路径；一次提交生效，失败不写入数据库且保留输入。
- [ ] 尚未创建项目时，PMC 能填写原因撤销判断并回到 OPEN；原判断与撤销原因保留在审计历史中。
- [ ] 已创建项目时撤销被 API 拒绝，不会让下游项目失去判断依据。
- [ ] 只有已决策任务可以创建并提交 `PRJ-OTD-001`。
- [ ] OWNER 能批准或退回；PMC 不能批准。
- [ ] RUNNING 项目允许 PMC 完成或重新打开子任务；其他状态拒绝更新。
- [ ] 节点进度等于已完成子任务数 / 子任务总数，页面和 API 均不接受人工百分比。
- [ ] 子任务重开必须填写原因，原完成与重开事件保留在审计历史。
- [ ] 4 个子任务全部完成时节点为 COMPLETED、项目仍为 RUNNING，等待未来真实结果验证。
- [ ] 子任务更新后老板驾驶舱显示派生项目进度与 Before / Current / Target。
